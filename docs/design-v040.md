## 0. 背景与范围

上游从 v0.3.5 到 v0.4.2 共 30+ 次提交。桌宠版是独立的 Electron 应用（无 DSH、无 webServer、
无插件路由），因此不能整包合并，只能按「事件同构 + 数据模型对齐」的方式移植：

- **移植**：泡泡框、音效四通道、长文本折行、设置保存可见化、连点/收起类交互修复
- **等价修复**：上游针对 web 布局的修复，在桌宠里用 CSS/渲染层等价实现
- **不移植**：DSH 注入 / 路由 / 插件市场 / Codex 统计 / 凭据外带防护（架构不同）

## 1. 自定义泡泡框

### 1.1 为什么需要「框」这一层

v0.3.5 的泡泡是**一块写死的 SVG**（`pet.js` 内联 path）。要换外观只能改代码，
且文字位置写死在 44.25% / 38%。上游 v0.4.0 把「外观」与「内容」拆开：
**框负责画外框和尾巴，安全区负责内容能占哪块区域**。

### 1.2 数据模型（`lib/frame.js`，纯函数）

```jsonc
// ~/.config/whale-pet/bubble-frame.json
{
  "v": 1,
  "sel": "round",          // classic | round | note | dashed | glass | frame_xxx
  "mirror": false,         // 左右版：整框水平翻转，尾巴换边
  "safe": null,            // null = 跟随框自带安全区；否则是用户微调后的覆盖值
  "custom": [              // 用户上传的框
    { "id": "frame_xxx", "name": "猫猫框", "format": "png",
      "tail": "none", "safe": { "x": 0.12, "y": 0.1, "w": 0.66, "h": 0.5 },
      "createdAt": 1792242608763 }
  ]
}
```

关键约束（全部有单测）：

- `safe` 是**画布归一化比例**（1026×700 的画布，不是像素），因此缩放窗口不会错位
- 消毒时先钳 `w/h ∈ [0.2, 1]`，再把 `x/y` 挤进 `[0, 1-w]`，**保证内容永远在画布内**
- `sel` 指向不存在/非法 id → 回退 `classic`（宁可回到默认框，也不渲染空白泡泡）
- 经典框的安全区特意取 `x=0.155,w=0.575,y=0.13,h=0.5`，
  中心正好是旧的 **44.25% / 38%** → 老用户升级后视觉零变化
- 自定义框：id 必须匹配 `[A-Za-z0-9_-]{1,64}`，重复 id / 与内置同名 / 非法 id 直接丢弃

### 1.3 镜像（左右版）

`effective(cfg)` 输出渲染层要用的最终几何：

```
safe' = { x: 1 - x - w, y, w, h }
tail' = left ⇄ right（none 不变）
```

镜像只影响**框与内容定位**，不改变序列内容；用户图片框同时水平翻转（`scaleX(-1)`），
这样带尾巴的图片框也能贴到屏幕左侧使用。

### 1.4 渲染层级（`renderer/pet.js` / `pet.css`）

```
.wp-bubble
├── <svg>              经典框（选中 classic 时显示）
├── .wp-gif            贴图
├── .wp-text           内置三行文字（按 --wp-safe-* 居中）
├── .wp-mods           自定义模块泡（按 --wp-safe-* 居中 + 限宽）
└── .wp-frame          新增：框层
    ├── .wp-frame-img  用户图片框（object-fit: fill，铺满画布）
    └── .wp-frame-card 内置框（CSS 画的圆角/便签/虚线/毛玻璃 + 尾巴伪元素）
```

- `pet.js` 把安全区写成 CSS 变量：`--wp-safe-x/y/w/h`、`--wp-mods-w`
- 内置框的卡片按安全区外扩 5% / 4.5% 定位，边框宽度与圆角都用 `--wp-u`（随鲸鱼缩放联动）
- 只有 `wp-frame-on` + `wp-bubble-open` 同时成立才显示框层（关闭泡泡时不会留一个空框）
- 切框时内容沿用原有淡入，避免「文字先于边框出现」

### 1.5 文件与 IPC

| 层 | 位置 |
|---|---|
| 模型 | `lib/frame.js`（消毒 / 解析 / 镜像 / 列表） |
| 持久化 | `lib/store.js`（`readFrame` / `setFrame` / `uploadFrame` / `deleteFrame` / `loadFrameImage`） |
| IPC | `frame:get` / `frame:set` / `frame:upload` / `frame:delete` / `frame:read` + 广播 `frame:changed` |
| 图片 | `~/.config/whale-pet/bubble-frames/<id>.png|gif`，目录 0700、文件 0600，上限 4MB |
| 设置页 | `renderer/menu-v040.js`（框库网格 + 镜像 + 安全区滑块） |

上传成功后**直接选中新框**（用户上传就是想看效果），删除当前框则回退 `classic`。

## 2. 音效四通道

### 2.1 通道映射

桌宠没有 DSH 的「提问 / 授权」事件，因此按**同构事件**落地，并在设置页写明触发时机：

| 通道 | 上游语义 | 桌宠版事件 | 默认 |
|---|---|---|---|
| `press` | 按压 / 松手 | `pointerdown` / `pointerup`，沿用当前音效组 | **开**，音量 100% |
| `cost` | 消耗 | 观测到余额下降（与旧「任务结束音」同一信号） | 关，80%，`frag:exp_orb` |
| `ask` | 提问 | 点击鲸鱼手动刷新余额 | 关，80%，`frag:d1` |
| `alert` | 授权（本版映射为提醒） | 刚进入低余额预警时响一次 | 关，100%，`frag:end_a` |

### 2.2 数据与优先级

```jsonc
"audioChannels": {
  "press": { "on": true,  "vol": 1,   "frag": "" },
  "cost":  { "on": false, "vol": 0.8, "frag": "frag:exp_orb" },
  "ask":   { "on": false, "vol": 0.8, "frag": "frag:d1" },
  "alert": { "on": false, "vol": 1,   "frag": "frag:end_a" }
}
```

- 实际音量 = 总音量 × 通道音量；总音量为 0 时所有通道静音
- `frag` 只接受 `frag:<合法片段 id>` 或空串（空串 = 该通道不发声）
- **消耗通道与旧「任务结束音」同信号**：消耗通道开启 → 由它接管；关闭 → 回退旧逻辑，
  保证老配置（`taskEnd.on`）行为不变，且不会两个都响
- 低余额提醒只在「从非预警进入预警」时响，不是每次刷新都响
- `applyAudioChannels` 只改现有 `Audio` 元素音量，**不重建**（重建会打断按下的音）

## 3. 设置界面：7 Tab → 5 Tab

### 3.1 信息架构

| 新 Tab | 合并来源 | 内容 |
|---|---|---|
| 账号 | 密钥 | API Key、平台令牌、维护（刷新 / 打开 config.json） |
| 数据 | 数据 | 用量模式、刷新间隔、低余额阈值、自启、记账数据 |
| 外观 | 界面 + 形象 | 主题、体型与闲置、菜单按钮、峰谷提示、预警/主/播报表情 |
| 气泡 | 文案 + 泡泡 | 气泡文字、随机台词、点击序列、模块编辑、**泡泡框**、预览 |
| 声音 | 音效 | 音效与音量、自定义音源、**音效通道** |

- 所有控件 **id 不变**，`menu.js` / `menu-v035.js` 无需改动绑定
- 分组支持折叠（`data-collapsible`，标题可点、可键盘 Enter/空格），默认展开
- 新增分组只碰 `wm-frame-*` / `wm-ch-*`，旧逻辑零侵入（新代码独立在 `menu-v040.js`）

### 3.2 顺手修掉的界面 bug

| Bug | 根因 | 修法 |
|---|---|---|
| 两个 Tab 同时高亮、内容和 Tab 不一致 | `switchTab` 把「显示页面」写在 tab 循环里，每轮都隐藏全部页面再显示当前 tab 的页 | 一轮循环同时处理高亮与对应页面显隐 |
| 保存失败毫无提示 | 所有 `setConfig` 都是裸 `.then`，失败只有看不见的 `saveError` 字段 | 统一 `saveConfig()` 出口：返回 `null` → 顶部 banner + 底栏「保存失败」 |
| 原生 `select` 在深色下是浅米色 | 新增通道片段下拉不在 `.wm-field` 内，没吃到既有深色样式 | `.wm-ch-frag` 显式上色 + 自绘箭头 |

## 4. 性能

| 改动 | 收益 |
|---|---|
| 设置窗**懒创建**（首次打开才 `new BrowserWindow`） | 启动少一个渲染进程，约省 70–90MB 内存；启动阶段不再跑菜单页初始化 |
| 设置窗等 `ready-to-show` 再显示 | 去掉首次打开的白屏闪烁 |
| 音效通道只改音量、不重建 `Audio` | 避免每次配置变更重新解码音频 |
| 内容定位改用 CSS 变量 | 换框/调安全区不触发布局重排，只改 `style` 变量 |

后续可做（P1，未在本版落地）：呼吸动画在窗口被遮挡时降频、余额/闲置定时器合并。

## 5. 兼容与迁移

- `CONFIG_VERSION` 2 → 3：启动时 `migrate()` 只补**缺失键**（`audioChannels`），
  已有值（含显式 `false` / `0` / 空串）原样保留，并先备份 `config.json.bak-v2`
- `bubble-frame.json` 不存在时视为 `classic`，**不写盘、不打扰老用户**
- `taskEnd`、`soundSet`、`audioGroup` 等旧键全部保留，旧行为不回归
- 经典框安全区按旧文字中心反推，升级后泡泡位置与原来一致
