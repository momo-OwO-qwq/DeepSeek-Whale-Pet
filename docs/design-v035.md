# v0.3.5 新功能移植与界面动画设计

> 目标：把上游 [MeteorNOX/DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)
> 自 **v0.2.8 → v0.3.5** 的新功能移植进本 Electron 桌宠，**只移植新功能**，
> 保留既有的基础余额显示与拖拽行为不变。
>
> 上游为 DSH Web 挂件（`ctx.webServer` 路由 + 浏览器 IIFE）；本工程是透明置顶的
> Electron 桌宠（主进程 Node + 渲染进程 Chromium + `preload` IPC 桥）。因此移植的
> 实质是**把「路由 + localStorage」换成「纯函数模块 + 原子写文件 + IPC」**，
> 同时保持上游的行为语义与视觉参数。

## 2. 架构：从「路由 + localStorage」到「纯函数 + IPC」

```
上游（DSH Web 挂件）                     本工程（Electron 桌宠）
────────────────────────────────────      ──────────────────────────────────────
/lib/index.js  ctx.webServer 路由   →     main.js        ipcMain.handle
$DSH_HOME/.dshw-bubble.json         →     lib/store.js   ~/.config/whale-pet/bubble.json
$DSH_HOME/whale-audio/audio.json    →     lib/audio.js   ~/.config/whale-pet/audio/
$DSH_HOME/whale-roles/roles.json    →     lib/assets.js  ~/.config/whale-pet/roles/
$DSH_HOME/whale-bubble-imgs/        →     lib/assets.js  ~/.config/whale-pet/bubble-imgs/
fetch('/dsh-whale/*.json')          →     preload.js     window.whaleAPI.*（contextBridge）
```

兑现方式（**这是本轮设计的核心决定**）：

1. **判定逻辑全部下沉为纯 Node 模块**，无 DOM、无 Electron 依赖。
   收益：`npm test` 可在不启动 Electron 的情况下完整覆盖（本环境无法下载 Electron 二进制，
   这是唯一可行的验证路径）。
2. **渲染进程不 require 任何东西**（`sandbox: true` + `contextIsolation: true` 未变），
   只通过 `window.whaleAPI` 取消毒后的配置。
3. **主进程负责消毒与持久化**，渲染进程不再解析脏数据 —— 上游是前端直读 localStorage
   并自行兜底，桌宠版把这份责任收归主进程，渲染层拿到的永远是合法值。

新增文件一览：

| 文件 | 职责 |
|---|---|
| `lib/bubble.js` | 泡泡配置模型：模块/行约束、消毒、加权抽样、点击状态机、占位符 |
| `lib/geometry.js` | 拖拽/定位几何：图形矩形归一化、窗口可停放范围钳制（空气墙修复） |
| `lib/audio.js` | 音效库模型：内置片段/组、槽位语义（空串=静音）、任务结束音序列 |
| `lib/assets.js` | 角色库与泡泡图库索引模型、dataURL 解析、文件扩展名规则 |
| `lib/store.js` | 上述四者的读写与**原子写**（tmp + rename，0600） |
| `renderer/menu-v035.js` | 设置界面：泡泡编辑器 |
| `test/v035.test.js` | 69 条单元测试（含与渲染层的一致性检查） |
| `test/geometry.test.js` | 29 条拖拽几何 / 空气墙 / 窗口裁剪回归测试 |

## 3. 自定义泡泡系统

### 3.1 数据模型

```jsonc
{
  "v": 1,
  "tapAdvance": false,          // 点按角色推进队列
  "items": [                    // 点击序列，按顺序推进
    { "kind": "normal" },                                  // 内置默认泡
    { "kind": "random" },                                  // 随机台词泡
    { "kind": "custom", "modules": [ /* module… */ ] },    // 自定义模块泡
    { "kind": "choice", "options": [                       // A/B 并列加权
        { "w": 10, "item": { "kind": "random" } },
        { "w": 1,  "item": { "kind": "custom", "modules": [] } }
    ]}
  ],
  "lib": [ { "id": "bmod_…", "name": "常用", "module": { } } ]   // 模块库
}
```

模块（`module`）字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | enum | `text` / `link` / `random` / `image` / `randimg` / `balance` / `today` / `peak` / `cost` |
| `text` | string | `text` / `link` 的正文（≤200 字符） |
| `tpl` | string | `balance`/`today`/`peak`/`cost` 的内容模板，含占位符 |
| `lines` | `[{t,w}]` | `random` 的候选句子与权重 |
| `imgId` / `imgs` | string / `[{id,w}]` | `image` / `randimg` 的图片 |
| `imgScale` | number | 图片缩放（0.2–4） |
| `size` | 1–50 | 字号档位（见 §3.3） |
| `color` / `rgb` | hex / 渐变键 | 纯色 / 跑马灯渐变文字色 |
| `bg` / `bgrgb` | hex / 渐变键 | 纯色 / 跑马灯底色 |
| `bold` / `italic` / `ul` | bool | 字形 |
| `wrap` | bool | 长句自动换行（`text` / `random`） |
| `row` | 正整数 | **行键**：同键模块同处一行；无键则自成一行 |

### 3.2 三条硬约束（编辑器与渲染层双重保证）

1. **每行最多 6 个模块**（`MOD_MAX = 6`）
2. **一个泡泡最多 6 行**（`ROW_MAX = 6`）
3. **图片类模块（`image` / `randimg`）独占一整行，且一个泡泡只允许一个**

第 3 条的「独占」有**两个独立后果**，实现时必须都处理：它既不能与任何模块同行，
也会**打断前后模块的行合并**。因此 `[{text,row:3},{image,row:3}]` 是 2 行而非 1 行。

### 3.3 字号联动

字号档位 `1..50` 线性映射到 `40u..240u`：

```
u(level) = round(40 + (level - 1) * 200 / 49)      // 1→40, 50→240
font-size = calc(u * var(--wp-u))                   // --wp-u = 窗口基准 / 1026
```

`--wp-u` 已由既有代码维护，因此泡泡模块与鲸鱼本体、气泡、动图**同一套缩放**，
改鲸鱼大小时模块字号自动跟随，无需额外监听。

### 3.4 点击推进状态机（关键：显示时自增）

上游 `whaleClick` 的语义必须原样保留，否则「第 1 项续时」与「回到第 1 项」会错位：

> **`bubbleSeqIdx` 在「显示时」自增**（`bubbleShowSeqNext` 内 `bubbleSeqIdx++`），
> 不是在下一次点击时自增。因此 `idx` 的含义是「下一条待显示的序号」，
> 而 `idx <= 1` 恰好表示「当前正显示第 1 项」。

| 状态 | `tapAdvance = false`（默认） | `tapAdvance = true` |
|---|---|---|
| 未显示 | 开新轮，从第 1 项开始 | 同左 |
| 正显示第 1 项（`idx<=1`） | **只续时**，内容不变 | 推进到下一项 |
| 第 2 项及以后 | **回到第 1 项** | 推进到下一项 |
| 已是最后一项 | — | **收起泡泡**，下次从第 1 项开始 |
| 非手动轮 | 不动作 | 不动作 |

### 3.5 加权随机

- **并列泡（A/B）**：每轮**独立**按权重抽一个候选，**不记忆上次**（上游明确注释）。
- **随机语句 / 随机图片**：抽 1 条/张，且**不连续重复**（上一次出现过的不再抽，
  池只剩 1 条时除外）。
- 权重经 `max(1, round(w))` 归一，0 或负数一律视为 1。

这两类随机行为**故意不同**：并列泡是「这一轮看哪种泡」，重复无妨；
台词/图片是「换个花样」，连续重复会显得像卡住。

### 3.6 占位符

`balance` / `today` / `peak` / `cost` 模块的 `tpl` 支持：

| 占位符 | 取值 |
|---|---|
| `{balance}` | 当前余额（含币种格式） |
| `{today}` | 今日已用 |
| `{status}` | 峰谷状态文字（高峰/空闲时段） |
| `{countdown}` | 距下一次峰谷切换的倒计时 |
| `{cost}` | 本轮消耗（桌宠版暂无数据源，显示 `--`） |

**未知占位符原样保留**（不替换、不清空），便于用户看出自己拼错了键名。
`text` / `link` / `random` 模块不做占位符替换（它们的文字是字面量）。

## 4. 拖拽定位与「缩放空气墙」修复

### 4.1 为什么删除吸附

上游的吸附（四边吸附区 + 翻转线 + 镜像）依赖「挂件即鲸鱼本体」这一前提。桌宠里
鲸鱼只占正方形窗口的右下 59.45%，照搬会出现两个问题：判定点必须按镜像态特殊处理，
且吸附会在缩放后把鲸鱼拽向边缘。桌宠本就以**自由拖拽**为手感，故本轮按需求整体移除：

- 删除 `lib/snap.js` 及全部相关测试
- 删除设置窗口的「吸附」Tab、`config.snap` 字段、`snap:get` / `snap:set` IPC
- 保留**方向感知锚点**（`flipped`）—— 它按屏幕左右半自动镜像鲸鱼朝向，
  与吸附无关，是「贴左边缘时鲸鱼面向屏幕内」的既有行为

> 注意区分：设置里的「隐藏菜单按钮」原本挂在吸附 Tab 下，已迁到「界面」Tab。

### 4.2 空气墙的成因

「由大变小时出现空气墙」= 窗口可停放范围按**旧窗口尺寸**计算，右/下留下
`新窗口 - 旧窗口` 宽的死区，无论如何拖都到不了屏幕边。

三处尺寸不同源，任一处不同步都会触发：

| 环节 | 旧行为 | 后果 |
|---|---|---|
| `dragState.fish` | `drag:start` 时存 **px 快照** | 拖拽途中缩放 → 钳制仍按旧尺寸 |
| `window:resize` | 立即返回**请求**尺寸 | 渲染进程按尚不存在的尺寸算 CSS/钳制 |
| `setScale` 钳制时机 | 改完 CSS 立刻 `settlePos` | `img.offsetWidth` 还是旧布局值 |

实测（Orange Pi 5 Plus / 1920×1080 / 任务栏 32px）：2.0 → 1.0 缩小后，
右侧死区正好 **320px** = 窗口尺寸差。

### 4.3 修复

1. **`lib/geometry.js` 收拢全部几何**（新增，可单测）
   `fishNormOf` / `fishFromNorm` / `windowRange` / `clampWindow`。
   main.js 里两处内联钳制公式全部删除，改为调用同一份实现。
2. **fish 存归一化比例**，不存 px 快照
   `dragState.fishNorm = {x,y,w,h}`（相对窗口的 0..1）。
   钳制时经 `currentDragGeom()` 按**此刻**窗口尺寸还原 → 缩放后自动跟随。
3. **`window:resize` 等真实尺寸落地再返回**
   轮询 `getContentBounds()` 直到等于请求值（上限 ~120ms），返回 `{width,height,settled}`。
4. **`setScale` 等一帧再钳制，并二次收敛**
   `await nextFrame()` 保证 `img.offsetWidth` 已按新布局更新；钳制后再等一帧复钳一次，
   处理镜像方向翻转带来的可见范围变化。

### 4.4 窗口裁剪已移除（v1.5.6）

曾用 `win.setShape()` 把窗口裁成「鲸鱼 / 气泡 / 按钮」区域，让其余透明处点击穿透。
现按用户要求**整体移除**，窗口保持完整矩形。三个实际踩到的问题：

| 问题 | 现象 |
|---|---|
| 气泡被一起裁掉 | 气泡展开时超出鲸鱼矩形就被切边（用户明确要求不要裁剪气泡） |
| 键名不合法 + 空 catch | Electron 的 `setShape` 只认 `{x,y,width,height}`，代码传 `{x,y,w,h}` → **每次都抛错并被静默吞掉**，窗口其实一直是完整矩形 |
| 缩放后 shape 未跟上 | 右下角那片不在裁剪区内 → 点不到、拖不动（「调整大小后拖不到右下角，重启才好」） |

代价：透明区域不再穿透，会挡住下方点击。取舍是**交互稳定 + 气泡完整 + 缩放后行为一致**。

`renderer/pet.js` 保留 `reportShape()` 空实现（散落调用点不必改动），主进程不再处理
`pet:shape`。

### 4.5 不变量（回归护栏）

`test/geometry.test.js` 锁定三条：

- **A. 无死区**：任意缩放（0.6–2.5）下，图形四条边都能精确贴到屏幕对应边
- **B. 阈值随尺寸走**：缩放后不残留旧尺寸（含 2.5→0.6→1.8 连续缩放）
- **C. 不越界**：图形不会被推出屏幕外
- **D. 不裁剪**：`main.js` / `pet.js` 均不得调用 `setShape`；气泡不被切边

另有一条**根因护栏**：显式断言「用旧尺寸 fish 钳制会留下 `窗口差` 宽的死区」，
把这个 bug 的机理固化下来，防止日后重构又退回快照式实现。

## 5. 音效与表情

### 5.1 槽位语义（血泪教训，别搞反）

音效组的 `press` / `release` 取值是**片段 id** 或**空串**：

| 取值 | 含义 |
|---|---|
| `''`（空串） | 该事件**显式静音**（不发声） |
| 合法片段 id | 播放该片段 |
| **字段缺失** | 视为旧数据 → **回退内置预设**（不是静音！） |

把「缺失」当「静音」会让只有一个音的音效组永久不发声。
任务结束音的「组」模式同理：**两个槽都空才静默返回，只空一个仍要播放另一个**
（上游 v729 的修复）。

另一个顺序陷阱：**每次点按的状态重置必须先于「没有 press 音频就 return」的短路**，
否则只有 release 的组只会响一次，之后永久静音。

### 5.2 表情图（预警 / 播报）

随包两张 610×610 RGBA cut-out（与主图同规格）：

| 素材 | 用途 | 触发 |
|---|---|---|
| `assets/DSniang-sad.png`（委屈） | 预警表情 | 余额 < 阈值（需开启 `alertImage`），叠加 `!` 徽标 |
| `assets/DSniang-happy.png`（开心） | 播报表情 | 余额下降（观测到一次消费） |

**优先级：预警 > 播报 > 自定义角色 > 主图** —— 预警是「必须看见」的状态，
不会被播报表情盖掉；预警期间继续下降仍保持预警表情。

播报表情保持 `dropImgHoldMs`（默认 2600ms，0 = 不切换）后自动回落。
与任务结束音共用「余额下降」这一个信号，两者同时触发。

> 两张素材原为黑底 WebP，导入时已做**黑底转透明**（按亮度软过渡 + alpha 归一化
> 去除半透明边缘的黑晕）并统一到 610×610 RGBA（否则桌面上会出现实心黑方块）。

#### 图内位置必须与主图对齐（重要）

**仅画布尺寸一致是不够的** —— 三张图必须是同一构图，否则切换表情时鲸鱼会在
桌面上「跳动」。导入时曾漏做这一步，实测三张图的可见区域差了约 22px。

对齐基准（以 `DSniang1.png` 为准）：

| 指标 | DSniang1.png | 对齐后 sad | 对齐后 happy |
|---|---|---|---|
| 白色女仆头饰左沿 | 169 | 170 | 169 |
| 白色头饰上沿 | 75 | 73 | 75 |
| 可见区域左沿 | 45 | 44 | 44 |
| 可见区域上沿 | 10 | 12 | 9 |

做法：以**白色女仆头饰的左上角**为主锚点、**可见区域 bbox 左上角**为副锚点，
取两者平移量的均值后整幅平移（三张图的人物缩放比例实测差异 <1%，因此纯平移
即可，无需缩放）。对齐后误差 ≤2px。

复核方法：解码三张图的 alpha 通道，比较「不透明像素 > 10」的包围盒左上角，
三者应在 2px 内一致。

### 5.3 任务结束音

```jsonc
{ "on": false, "sel": "frag:exp_orb", "pins": [] }
```

- **默认关闭**，但默认已选中内置「Minecraft·经验球」→ 打开即用。
- `sel` 语法：
  - `frag:<片段id>` → 单个音频片段
  - `preset:<组id>:<press|release>` → 内置组的某一槽
  - `grp:<组id>` → 模拟一次完整点按（先 press，`onended` 后 release）
- 内置片段 `exp_orb`（经验球，mono/48k/0.62s）与 `end_a`（A，stereo/48k/1.66s）
  随包发布；MIME 必须与字节一致（`audio/wav`），否则解码异常。

## 6. 桌宠与网页版的语义差异（重要）

| 上游 | 桌宠版本轮实现 | 理由 |
|---|---|---|
| 任务结束音由 `turn/end` 会话事件触发 | 由**观测到余额下降**触发 | 桌宠独立运行，没有 DSH 会话事件流。余额下降 = 已发生一次消费，是无令牌下最接近的信号。已用注释标明这一近似。 |
| `{cost}` 取自本轮真实 usage | 显示 `--` | 同上，无逐轮 token 数据源。 |
| 逐轮消耗泡泡 | 不实现 | 属下一阶段（需 Codex/DSH 数据源）。 |
| 配置在 localStorage | 配置在 `config.json` / 独立 json 文件 | 桌面应用无同源 localStorage 语义，且需 0600 权限保护。 |

## 7. 界面与动画规范

### 7.1 鲸鱼窗口（`renderer/pet.css`）

| 元素 | 动画 | 时长 / 缓动 |
|---|---|---|
| 自定义泡泡逐行进入 | `opacity 0→1` + `translateY 8u→0` | `.34s cubic-bezier(.22,1,.36,1)`，**逐行错峰 70ms** |
| 泡泡开合（既有） | 三个 SVG 形体依次缩放 | 开：`b2 0s → b1 .13s → bshape .26s`；合：反向 |
| 内容切换 | 淡出 → 换内容 → 淡入 | 出 `.18s` / 入 `.22s`（190ms 切换点） |
| 跑马灯渐变文字 | `background-position 0→200%` | `2.6s linear infinite` |
| 跑马灯底色 | 同上 | `3.2s linear infinite`（比文字慢，避免视觉打架） |
| 按压 Q 弹（既有） | `scaleY(.88) scaleX(1.05)`，原点 `50% 100%` | `.22s cubic-bezier(.34,1.56,.64,1)` |
| 数字滚动（既有） | 700ms ease-out 三次方 | 变化后延迟 300ms 起滚 |

**节奏家族**：所有「内容出现」类动画都用同一条 `cubic-bezier(.22,1,.36,1)`
（快速起步、长尾收束），只是时长按信息量分级 —— 单行 .34s、整体开合 .26s/段。

### 7.2 设置窗口（`renderer/menu.css`）

| 元素 | 动画 | 时长 / 缓动 |
|---|---|---|
| 预览逐行进入 | `opacity 0→1` | `.26s` 同款缓动，**逐行错峰 26ms** |
| 序列条目悬停 | 边框变色 | `.16s ease` |
| 拖拽中的源条目 | `scale(.98)` + `opacity .55` + 投影 | `.16s ease` |
| 拖拽落点 | 边框转**虚线** + 强调色 | 即时 |
| Tab 切换 | 无动画（保持既有行为） | — |

设置窗口的错峰（26ms）比鲸鱼窗口（70ms）更密，因为它是**预览**——
用户要看整体节奏，不是逐行阅读。

### 7.3 无障碍

两个窗口都实现 `prefers-reduced-motion: reduce`：

- 鲸鱼窗口：关闭跑马灯流动与逐行进入（模块直接可见）
- 设置窗口：关闭预览淡入与条目过渡

### 7.4 触控与鼠标

| 场景 | 手势 |
|---|---|
| 唤出设置（桌面） | **右键鲸鱼**（开启「隐藏菜单按钮」后） |
| 唤出设置（触屏） | **长按约 1.5s**，位移 >10px 取消 |
| 泡泡序列排序（桌面） | 原生 HTML5 拖拽 |
| 泡泡序列排序（触屏） | **长按 400ms** 进入拖拽 |
| 模块内移动 | `←` / `→` 与前后模块交换 |

触屏**即使未开启**「隐藏菜单按钮」也允许长按唤出 —— 无 hover 的设备否则没有入口。

## 8. 验证

本环境无法下载 Electron 二进制（`electron install` 报 ECONNREFUSED），因此
**验证手段是纯 Node 单元测试 + 静态一致性检查**：

```bash
npm test        # 8 条既有 + 69 条 v0.3.5 + 29 条几何 = 106 条，全部通过
```

`test/v035.test.js` 覆盖：

- **泡泡**：字号映射、图片独占行与打断合并、`row` 键分组、`rowsFlat` 单模块行不写键、
  6/6 上限、拆行/排序、单图限制、消毒丢弃未知字段、默认加粗、choice 最多 2 候选、
  权重下限、加权抽样、防连续重复、**点击状态机全五态**、占位符。
- **音效**：内置片段/组不可删、任务结束音默认关闭、`sel` 语法、
  **空串=静音 vs 缺失=回退**、两槽都空才静默、**v729 状态重置顺序**、
  索引消毒、排序规则、MIME 一致性、路径不可穿越。
- **资源库**：角色消毒**幂等**（重复消毒不增殖 `default`）、排序、扩展名规则、
  png/gif 与 webp 的格式差异、内置图优先且重名不重复。
- **持久化**：往返一致、WAV 头校验、删除不留孤儿文件、内置资源可读、
  缺失资源不抛异常、原子写不留 tmp、**文件权限 0600**。
- **一致性护栏**：渲染层内联的字号公式与行归组规则必须与 `lib/bubble.js` 同源；
  长按阈值 1500ms/10px、拖拽 400ms 与上游一致；CSS 类名与 JS 切换的类名一致；
  新资源目录都在配置目录内。

> 渲染进程无法 `require`，所以 `pet.js` / `menu-v035.js` 各有一份行归组与字号的
> 内联实现。上面的「一致性护栏」用例就是防止这两份实现悄悄漂移 —— 这是本次
> 设计里最容易被忽视的风险点。
